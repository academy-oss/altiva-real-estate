# ALTIVA Real Estate — موقع الشركة

موقع تعريفي واستثماري لشركة **ألتيفا العقارية**، مبني بمطابقة بصرية كاملة لهوية الموقع المرجعي (الألوان الكحلية/الذهبية/الكريمية، الخطوط، الشعار، الحركات)، مع دعم كامل للغتين العربية والإنجليزية (RTL / LTR) وربط فعلي مع **Zoho CRM**.

نماذج الاستشارة والتواصل ترسل مباشرة إلى وحدة Leads في زوهو. أما المشاريع فمصدرها الرئيسي وحدة `Real_Estate_Projects`، وتُنشر إلى الموقع تلقائيًا كل 30 دقيقة بعد تفعيل مفاتيح المزامنة المشفرة في GitHub.

---

## 1. المتطلبات

- Node.js 18 أو أحدث (تم تطويره واختباره على Node 22)
- npm 10 أو أحدث

## 2. التشغيل محليًا

```bash
# تثبيت الحزم
npm install

# تشغيل بيئة التطوير (مع Hot Reload)
npm run dev

# بناء نسخة الإنتاج
npm run build

# معاينة نسخة الإنتاج المبنية محليًا
npm run preview

# فحص الأخطاء البرمجية (lint)
npm run lint
```

بعد `npm run dev` يفتح الموقع تلقائيًا على `http://localhost:5173`.

## 3. متغيرات البيئة

انسخ ملف `.env.example` إلى `.env` عند الحاجة الفعلية لإعداد الربط مع Zoho:

```bash
cp .env.example .env
```

الملف لا يحتوي على أي أسرار — فقط أسماء المتغيرات التي ستحتاجها لاحقًا (رابط الـ API، اسم الموديول، رقم واتساب، بيانات التواصل، إلخ). راجع تعليقات الملف نفسه لمزيد من التفاصيل.

### لماذا هذا التقسيم؟

كل مكون في الواجهة يقرأ بيانات المشاريع **فقط** من خلال `src/services/projectsService.ts`. الملف `public/data/projects.json` هو نسخة النشر المولدة من زوهو، بينما تبقى البيانات المحلية خيارًا احتياطيًا يحمي الموقع إذا تعذرت المزامنة.

## 5. الربط مع Zoho CRM

- وحدة `Real_Estate_Projects` هي المصدر الرئيسي للمشاريع؛ لا يوجد دخول منفصل للموظف إلى الموقع.
- فعّل **Publish on Website** ليظهر المشروع، و**Featured on Website** ليظهر ضمن المشاريع المختارة في الرئيسية.
- ارفع حتى 10 صور في **Website Images**؛ أول صورة تصبح الغلاف والبقية معرض المشروع.
- ارفع ملفات PDF في **Website Brochures**، مع كتابة `AR` أو `Arabic` في اسم الملف العربي و`EN` أو `English` في اسم الملف الإنجليزي.
- يمكن إبقاء حقول روابط الصور والبروشورات القديمة كخيار احتياطي للمشاريع الحالية.
- مهمة `.github/workflows/sync-zoho-projects.yml` تقرأ المشاريع كل 30 دقيقة، ولا تعمل إلا بعد إضافة `ZOHO_CLIENT_ID` و`ZOHO_CLIENT_SECRET` و`ZOHO_REFRESH_TOKEN` كأسرار مشفرة في إعدادات GitHub.
- مفاتيح OAuth لا توضع أبدًا داخل ملفات الموقع أو أي متغير يبدأ بـ `VITE_`.
- نماذج الاستشارة والتواصل تستخدم نموذج Zoho Web-to-Lead الرسمي، وتُسجل `Lead Source = Website` مع تفاصيل الطلب وموافقة الخصوصية.

## 6. استبدال البيانات التجريبية

- فلاتر الإمارات السبع وأنواع العقارات ونطاقات الأسعار موجودة حتى لو لم تتوفر مشاريع في بعض الخيارات بعد.
- النسخة العامة المحلية تعرض أربعة مشاريع موثقة من الموقع المرجعي بصورها الأصلية. السجلات التجريبية الأخرى مخفية تلقائيًا ولا تظهر للزوار.
- الشعار المستخدم (`src/assets/brand/altiva-icon.png`) هو **نفس الشعار الأصلي** من الموقع المرجعي، ويجب عدم استبداله أو تصميم شعار بديل.

## 8. الصفحات المتوفرة

| المسار | الوصف |
|---|---|
| `/` | الرئيسية (Hero، لماذا دبي، مشاريع مختارة، من نحن، خدماتنا، إحصائيات، شركاء، حاسبة العائد، آراء العملاء) |
| `/projects` | قائمة المشاريع مع الفلاتر الكاملة |
| `/projects/:slug` | تفاصيل مشروع واحد |

| `/contact` | تواصل معنا |
| `/privacy` | سياسة الخصوصية |

## 9. فلاتر المشاريع

تدعم صفحة `/projects` الفلاتر التالية بالكامل: الإمارة (السبع جميعها)، المنطقة (تُحسب ديناميكيًا من بيانات المشاريع المتاحة)، نوع العقار (12 نوعًا)، نطاق السعر (من أقل من 500 ألف إلى أكثر من 10 ملايين درهم)، عدد الغرف، المطوّر، حالة المشروع، وموعد التسليم — بالإضافة إلى بحث نصي حر.

## 10. نموذج طلب الاستشارة

يشمل نموذج `/consultation` جميع الحقول المطلوبة: الاسم، الهاتف، البريد الإلكتروني، بلد الإقامة، الإمارة المهتم بها، نوع العقار، الميزانية، الهدف من الشراء، موعد الشراء المتوقع، عدد الغرف، طريقة التواصل المفضلة، ملاحظات إضافية، والموافقة على سياسة الخصوصية (إلزامية لإتمام الإرسال).

- **React 19** + **TypeScript**

## 12. ملاحظة حول الشعار والصور

هذا المشروع يستخدم الشعار وصور الفريق وصور المشاريع الأربعة من الموقع المرجعي. صور المشاريع والبروشورات الجديدة تُرفع في سجل المشروع داخل زوهو وتُنشر آليًا، من دون كشف بيانات الدخول في المتصفح.

## 13. مستشار ALTIVA الذكي

- المساعد العائم يدعم العربية والإنجليزية ويقرأ نفس ملف المشاريع المنشور آليًا من Zoho.
- عند تعطل خدمة الذكاء الاصطناعي، يبقى البحث والترشيح الأساسي متاحًا للزائر من خلال نسخة محلية آمنة.
- نموذج طلب التواصل داخل المساعد لا يرسل بيانات العميل إلا بعد الموافقة، ثم يسجل الطلب في Leads عبر ربط Zoho الحالي.
- الجزء الخلفي موجود في مجلد `worker/` ويستدعي OpenAI من الخادم فقط. مفتاح `OPENAI_API_KEY` يجب حفظه كسر مشفر في Cloudflare Worker ولا يوضع داخل ملفات الموقع أو متغيرات `VITE_`.
- بعد نشر العامل، يوضع رابطه العام في `VITE_ASSISTANT_API_URL` أثناء بناء الموقع.
